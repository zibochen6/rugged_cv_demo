# Visual Hub Jetson GUI 与画面全屏监视 - 需求契约

> 状态：`frozen`。本文档是需求事实源，不包含技术方案或实现计划。任何变更都必须记录在“版本与决策记录”并重新确认。

## 背景与问题

- 触发场景：Jetson 既需要通过局域网 Web 总控使用，也需要在连接显示器时直接从设备桌面进入同一套总控。
- 当前做法与痛点：Web 总控已有同页放大视图，但缺少明确的显示级全屏入口；Jetson 桌面也没有可一键打开总控的 GUI 入口。
- 不解决的影响：现场人员需要手工打开浏览器和输入地址，单路重点监视时画面利用率不足，且不同入口可能出现功能不一致。

## 目标用户与场景

| 使用者 | 场景 | 需要完成的动作 | 当前障碍 |
| --- | --- | --- | --- |
| 远程监控人员 | 在局域网浏览器查看三路总控 | 将任一摄像头切换为全屏并返回总控 | 当前只有同页放大，缺少明确全屏按钮 |
| Jetson 现场操作人员 | 设备连接显示器后进行本地监控 | 从桌面一键打开总控、全屏查看单路并返回 | 当前没有桌面 GUI 启动入口 |

## 目标与非目标

### 目标

- Web 与 Jetson 桌面 GUI 使用同一套三路视觉总控能力。
- 每个摄像头画面均可通过明确按钮进入全屏监视。
- 全屏监视可以可靠返回三路总控，并且不影响正在运行的推理。
- Jetson 连接显示器时可从桌面一键启动 GUI，并可展开为全屏使用。

### 非目标

- 不新增一套与 Web 总控独立的原生桌面业务界面。
- 不要求登录桌面后自动启动 GUI。
- 打开 GUI 或进入全屏时不自动启动三路推理。
- 本次不把后视距离、蜂鸣器或座舱开关复制到单路全屏页。

## 范围

### 本次包含

- 前视、后视、座舱三个画面的全屏入口。
- 可见返回按钮和 `Esc` 返回行为。
- 浏览器无法进入显示级全屏时的页面内放大降级行为。
- Jetson 桌面的一键 GUI 入口及重复启动保护。
- 前视全屏中的正点、负点选目标和清除目标操作。
- 后视与座舱全屏中的实时画面和运行状态。

### 本次不包含

- 单独维护桌面版前端代码或不同的业务逻辑。
- 自动开始、停止或重启推理。
- 在后视或座舱全屏中编辑详细配置。
- 修改三路摄像头固定绑定关系。

## 业务规则

- 点击任一摄像头的全屏按钮，只改变显示方式，不重启视频流、摄像头或模型。
- 全屏期间三路总控的后台状态和推理生命周期保持不变。
- `Esc` 与可见返回按钮都必须退出单路全屏并回到三路总控。
- 当前环境不支持显示级全屏时，仍必须提供可返回的页面内大画面。
- 前视全屏保留交互式分割能力；后视和座舱全屏只提供监视与状态。
- 桌面 GUI 启动后停留在总控，不自动调用“一键全开”。
- 桌面 GUI 已打开时再次点击入口，不应创建多个重复实例。

## 约束

- 继续以 `http://192.168.6.84:8000/` 作为唯一总控服务入口。
- 桌面入口仅在 Jetson 有可用图形显示会话时使用。
- Web 和桌面 GUI 必须保持相同的核心操作与状态语义。
- 页面关闭不代表停止推理；资源释放仍由总控的显式停止操作和服务生命周期负责。

## 验收标准

| ID | 可观察的结果 / 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | Web 总控查看三路画面 | 每个画面都有可识别、可聚焦并带提示的全屏按钮 |
| AC-02 | 点击某一路全屏按钮 | 该路画面占据当前显示区域，其他总控内容不干扰监视 |
| AC-03 | 从全屏返回 | 点击可见返回按钮或按 `Esc` 均回到三路总控 |
| AC-04 | 全屏切换期间持续推理 | 模块进程、摄像头连接和模型不因进入或退出全屏而重启 |
| AC-05 | 前视全屏操作 | 正点、负点选择与清除目标可用，坐标映射正确 |
| AC-06 | 全屏能力不可用 | 自动使用页面内大画面，且仍可返回总控 |
| AC-07 | Jetson 连接显示器 | 用户可从桌面一键打开总控 GUI，并可全屏使用 |
| AC-08 | 重复点击桌面入口 | 不产生多个重复 GUI 实例，已有实例可继续使用 |
| AC-09 | 打开桌面 GUI | 三路推理状态不被自动改变 |
